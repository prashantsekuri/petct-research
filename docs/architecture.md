# Architecture

## Status and safety boundary

This project is research tooling and is not a clinical diagnostic system.
Original DICOM studies live outside the repository and are always treated as
read-only. The pipeline must never modify, rename, delete, anonymize, or write
into a source study directory, and patient data must never be uploaded.

Common DICOM filename patterns are ignored by Git as a secondary safeguard, but
DICOM files can have no extension. Ignore rules therefore cannot guarantee
protection. The actual rule and system boundary is that source patient data must
remain outside the repository.

Derived artifacts will be written beneath the local `output/` directory. Its
contents are not committed to Git. Because DICOM metadata can contain PHI, any
future metadata export must select fields through an explicit allowlist and must
never dump every available tag.

## Intended pipeline

```text
DICOM discovery
-> series inventory
-> PET metadata validation
-> quantitative PET/SUV validation
-> DICOM-to-NIfTI derived volumes
-> anatomy segmentation
-> PET lesion segmentation
-> deterministic measurements
-> evidence package
-> optional LLM interpretation
```

Read-only DICOM discovery, series inventory, PET metadata inspection, and the
approved PET SUVbw/CT HU derived NIfTI conversion are implemented. Conversion
writes only beneath `output/`, preserves source DICOM as read-only, and performs
no registration or resampling. Segmentation and later stages are not
implemented.

## Deterministic quantitative results

Quantitative values, including SUV, lesion size, coordinates, volume, and
radiomics, must be generated by deterministic imaging code. They must never be
invented, estimated, altered, or corrected by an LLM.

An optional LLM may interpret a completed evidence package, but it may not
change the measurements or become their source of record. The evidence package
must preserve the deterministic results supplied to that interpretation stage.
